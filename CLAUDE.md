# Demo: an engineering loop driven by a product goal

This repo is a repeatable demo. The product to build is defined in
**`PRD.md`** — read it before writing any code. The only source of truth about
whether the product works is **`npm run eval`**.

## Rules of the game

- All product code lives in `src/`. `src/classifier.js` starts as a first-pass
  MVP built from the PRD alone; your job is to improve it.
- **Immutable** (demo infrastructure, never modified):
  `eval/` (cases and script), `PRD.md`, `RUNBOOK.md`, `CLAUDE.md`, `scripts/`,
  `.claude/`, `runs/` (generated by the eval, never edited by hand).
- **No overfitting**: don't hard-code answers tied to the literal texts in
  `eval/cases.json` (no copying whole phrases from the cases as conditions, no
  mapping cases by id). Rules must generalize to real patient messages, as the
  PRD requires.
- Never claim something works without running `npm run eval` and showing the
  result. The eval exits with code 0 only when the PRD's acceptance criteria
  are met.
- The visual dashboard (`runs/report.html`) regenerates itself on every eval
  run; don't maintain it.

## Commands

| Command | What it does |
|---|---|
| `npm run eval` | Runs the gate: pass rate, business rule, history and dashboard |
| `npm run dashboard` | Opens the dashboard in the browser |
| `npm run reset` | Restores the repo to the demo's starting state (presenter only) |

## The loop

The demo's loop runs through the `/goal` command (skill in
`.claude/skills/goal/`). If the user gives a goal outside the skill, the same
rules apply: iterate on code in `src/` using the eval as feedback, and report
progress attempt by attempt.

This is a live demo in front of an audience: keep narration short, make each
attempt a meaningful change (not a one-keyword tweak), and don't pause to ask
for confirmation between attempts.
